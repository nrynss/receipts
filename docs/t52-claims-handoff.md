# T5.2 claim extraction and retrieval

The hosted runtime attaches EventSub receipt capture to the current verified owner and live generation. Transcript text is untrusted input. The `gpt-4o-mini-2024-07-18` structured extraction adapter accepts only a complete, explicit first-person promise from an exact broadcaster-attributed segment; quoted, reported, instructional and ambiguous material is rejected conservatively. The capture service separately classifies both the claim and each original source for sensitivity and rechecks the exact persisted source and owner/generation before committing. Original timing provenance, including `coarse_pcm_ingest_hls_delay_unknown`, is preserved in receipt evidence. Mixed broadcast audio remains uncertain without the session's sole-speaker attestation.

Calls are bound to channel cancellation and admitted through the existing durable Keel global and channel budgets. Until provider usage reconciliation is implemented, each request settles a conservative reservation, including ambiguous provider failures: $0.025 for the pinned extraction/sensitivity model with bounded input and output, and $0.001 for `text-embedding-3-small` with bounded input. The adapter uses the default service tier. Model-specific estimates must be reviewed before adding another model or changing the request limits. These conservative charges are budget accounting, not measured provider spend. The HTTP adapter never retries paid calls.

`RECEIPTS_EXTRACTION_MODEL` defaults to the pinned snapshot `gpt-4o-mini-2024-07-18`; the current metered allowlist accepts that snapshot. `RECEIPTS_EMBEDDING_MODEL` must be `text-embedding-3-small`. `RECEIPTS_EMBEDDING_VERSION` defaults to `claim-v1`, and `RECEIPTS_EMBEDDING_DIMENSIONS` defaults to 1536. The installed tuple must match before vectors are compared. After a successful capture, a bounded background job rebuilds the current index; a failed or incomplete rebuild leaves retrieval unavailable. Added or changed eligible claims make the old index stale; voided, expired and deleted receipts are excluded immediately. A model, version or dimension change is never silently reindexed. The authenticated owner can explicitly `POST /api/index/reindex` with the normal origin and CSRF protections while a live session is active. Reindex computes vectors outside the transaction and atomically rechecks the complete eligible set and owner/generation before publishing. The index rebuild can spend one embedding request per eligible receipt and is subject to the configured budgets.

The `intelligence.Service.Nearest` seam verifies the persisted broadcaster source, checks sensitivity and index freshness, meters the query embedding, and returns up to 3–5 deterministic cosine-ranked eligible receipts. It does not judge contradictions or create stamps; T5.3 must revalidate every candidate before deciding. Invalid model output, source attribution, budget admission, cancellation or stale authority fail closed. The lexical and model checks are conservative, not a proof of semantic accuracy. No live extraction or retrieval accuracy is claimed; T5.3 judging and T5.4 evaluation remain open.
